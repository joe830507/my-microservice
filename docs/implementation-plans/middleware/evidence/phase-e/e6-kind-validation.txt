## SMTP 整合測試與 Windows Docker Desktop 解法

- 原本 Testcontainers 將 SMTP 暴露到 host mapped port；Windows Docker Desktop 上 TCP 可連，但 SMTP server-first greeting 無回應，因此兩個真實 SMTP 測試失敗。
- 依使用者選定方案，Mailpit SMTP 僅在 Testcontainers network 內以 `mailpit:1025` 提供；Testcontainers 以同 network 啟動從目前原始碼建置的 notification-service runner，使用相同 PostgreSQL 測試資料庫。Host 僅透過 mapped HTTP port 8025 查 Mailpit API。被測派送仍由正式 `EmailDispatcher`／`JavaMailSender` 透過 SMTP 完成，沒有 mock 或放寬斷言。
- 整個 `NotificationEmailIntegrationTests` 類別通過：事件消費、六封唯一佇列、五種範本、收件人與內文、重複事件去重、併發 dispatcher `SKIP LOCKED`、暫時性 SMTP 失敗及缺少收件人的 SKIPPED 路徑均保留並驗證。
- Mailpit API 詳細內容與原始 headers 確認每封信的 `Message-ID` 為 `<{email_message.id}@my-microservice.local>`；確認 Bcc 收件人欄位為空。另加範本注入斷言：名稱含 `{{amount}}` 時保留原字串，不被金額替換；`{{name}}` 改為最後替換。
